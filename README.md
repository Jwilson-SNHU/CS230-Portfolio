## CS 230 Portfolio Reflection – Draw It or Lose It

The client for this project was The Gaming Room, a company that wanted to expand their game, Draw It or Lose It, beyond Android to multiple platforms. The goal was to design a web-based application that could support multiple users, teams, and game sessions at the same time. The software needed to be scalable, secure, and accessible across different devices such as desktops and mobile platforms.

One thing I did well in developing this documentation was clearly breaking down the system requirements and connecting them to real technical solutions. I feel like I improved a lot in explaining technical ideas in a way that makes sense from both a developer and client perspective. Working through the design document also helped me understand how important planning is before writing code. It made it easier to think about how everything fits together, especially when dealing with things like APIs, distributed systems, and platform compatibility.

If I could revise one part of my work, I would probably spend more time going deeper into system architecture diagrams or visuals. I think adding more visual elements would make the design even easier to understand and more professional. I focused more on written explanations, but visuals would strengthen the overall presentation.

When interpreting the user’s needs, I focused on scalability, performance, and accessibility. Since the game involves multiple players interacting in real time, it was important to design a system that could handle high traffic and run smoothly across platforms. Considering user needs is important because if the system does not perform well or is difficult to access, users will not have a good experience, no matter how well the code is written.

My overall approach to designing the software was to break the system into smaller parts and focus on how each part interacts with the others. I used concepts like the client-server model, REST APIs, and cloud-based architecture to guide my design decisions. In the future, I would continue using this structured approach and spend more time evaluating trade-offs between performance, cost, and scalability before finalizing a design.
